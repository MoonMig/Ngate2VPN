# Ngate2VPN

Клиент macOS для управления несколькими VPN-туннелями Ngate (КриптоПро NGate).
Написан на SwiftUI, работает поверх штатного `ngateconsoleclient`, с дизайном
в духе Shadowrocket и нативной эстетикой macOS.

> **Статус:** v4.00 — production-ready (Apple Silicon, macOS 13+)

---

## Возможности

### Несколько профилей в одном окне
- Любое количество туннелей в едином интерфейсе; у каждого своё состояние, журнал и учётные данные
- Перетаскивание для изменения порядка
- Правый клик по профилю: **Edit Profile**, **Move Up / Move Down**, красный **Delete Profile**
- Клик по строке профиля ничего не открывает — переключатель и меню правого клика исключают случайные срабатывания
- Редактор профиля открывается как sheet
- Клик по IP-адресу подключённого туннеля копирует его в буфер обмена (кратко показывается «Copied»)

### Интерфейс из трёх разделов
- **Главная (Home)** — список профилей с переключателями, Connect All / Disconnect All
- **Журнал (Journal)** — единый поток логов всех туннелей с фильтрацией
- **Настройки (Settings)** — параметры приложения, DNS Helper, тема

Кнопки вкладок размещены прямо в заголовке окна macOS рядом с кнопками управления.

### Быстрое подключение (прогрев)
`ngateconsoleclient` при каждом запуске читает все контейнеры токена (JaCarta и т. п.):
~12 секунд на процесс, причём токен обслуживает процессы по очереди.
Ngate2VPN прячет это время за запуском приложения:

- **Pre-warm** — клиенты для туннелей по сертификату запускаются заранее (при старте приложения,
  вставке токена, пробуждении из сна и в момент Disconnect) и удерживаются перед первым сетевым
  подключением; по нажатию Connect уже инициализированный процесс отпускается, и туннель
  поднимается за секунды. Connect All с прогретыми клиентами — порядка 8–9 секунд вместо ~40.
- **Парольные туннели** запускаются в песочнице без доступа к токену (инициализация ~0,3 с),
  поэтому им прогрев не нужен.
- Прогретые клиенты не видны watchdog'у и статусам, пока Connect их не «усыновит»; устаревшие
  (старше 10 минут) обновляются автоматически; настройка отключается в
  Settings → Application → *Pre-warm tunnels*.

### Надёжная обработка соединений
- Watchdog с экспоненциальной паузой между попытками (5 с → 15 мин)
- **Повторяемые ошибки** → авто-переподключение; **критические** → остановка и уведомление
- Пределы попыток: 8 подряд без Auto-reconnect, 24 с ним (~5 часов), затем пауза и уведомление;
  после пробуждения из сна пауза Auto-reconnect-туннелей снимается
- Connect All продолжает подключение остальных туннелей при ошибке одного
- Распознавание более 30 типов сообщений ngate-client

### Туннели с 2FA (логин + пароль + подтверждение в приложении)
Шлюз держит парольный вход ~15 секунд, ожидая подтверждения второго фактора, и затем отвечает
«отказано» — внешне неотличимо от неверного пароля. Ngate2VPN различает эти случаи по времени
ответа: отказ после ≥ 8 с — это **пропущенное подтверждение**, а не неверный пароль.
Приложение делает ровно **2 попытки** (каждая шлёт новый push), потом ставит туннель на паузу
и показывает понятное сообщение. Быстрый отказ показывается как «Login rejected by the gateway…» без уверенных утверждений о причине (неверный пароль, отклонённый push и временная блокировка выглядят одинаково).

### Проверка системного прокси
`ngateconsoleclient` ходит к шлюзам через **системный** прокси macOS. Если прокси (например,
Shadowrocket) не работает, попытки заканчивались невнятными ошибками. Теперь при каждом
подключении в фоне выполняется реальный `CONNECT` через прокси, выбранный для адреса шлюза
(с учётом списка исключений), и при сбое в журнале появляется предупреждение с именем прокси и
подсказкой добавить шлюз в исключения. Ошибки прокси классифицируются отдельно и повторяются.
Подключение эта проверка не блокирует.

### Светлая и тёмная темы
- Три режима: **System**, **Light**, **Dark**; цвета адаптируются по всему интерфейсу

### DNS Helper — split-DNS без боли
Автоматическое создание `/etc/resolver/<domain>` так, чтобы запросы к корпоративным доменам шли
через VPN, а всё остальное — напрямую. Подробности — в разделе [DNS Helper](#dns-helper).

- **Один диалог пароля** при установке — всё остальное без запросов
- Автоматический подхват DNS-настроек из ответа шлюза
- Автоматическая очистка при выходе и переподключении туннелей
- Toggle **Hold Default DNS** (по умолчанию включён): системный DNS не трогается

### Безопасное хранение данных
- PIN-коды и пароли всех туннелей хранятся **в одном элементе macOS Keychain** — один запрос
  доступа на все туннели, а не по запросу на каждый секрет
- Стабильная подпись сборок (локальный сертификат) — «Always Allow» для Keychain переживает обновления
- Секреты никогда не попадают в `UserDefaults`, логи и резервные копии настроек
- Конфиги клиента с учётными данными создаются на время запуска с правами `0600` и удаляются
  сразу после завершения процесса
- Профили переживают обновления приложения: чтение настроек терпимо к новым полям, а перед
  перезаписью сохраняется резервная копия (без секретов)

### Полноценное логирование
- Логи по каждому туннелю в разделе Journal; единый поток сортируется по времени
- Фильтры: **Errors**, **Info**, **Debug**, **System**; выделение и копирование, автопрокрутка
- Ротация логов (5 МБ) и очистка через 30 дней; полностью асинхронная запись
- Системные события `[SYSTEM]` несут явный уровень (`Info` / `Warning` / `Error`) и окрашиваются по уровню
- Единый формат времени `dd.MM.yyyy HH:mm:ss.SSS`
- Файлы логов: `~/Library/Application Support/Ngate2VPN/logs/`

### Настройки
- **Автоподключение при запуске**
- **Pre-warm tunnels** — прогрев клиентов (см. выше)
- **Показывать ошибки** — отключение всплывающих окон
- **Скрывать из Dock при закрытии** — фоновый режим
- **Тема** — System / Light / Dark
- **DNS Helper** — установка / удаление / Hold Default DNS
- `ngateconsoleclient` всегда запускается с `-vvvv`: DNS Helper берёт DNS-настройки шлюза из
  verbose-вывода

### Интеграция в трей
- Иконка в статус-баре с цветовой индикацией: серый — всё отключено, светло-синий — один туннель
  подключён, тёмно-синий — часть, зелёный — всё подключено
- Меню: открыть окно, Connect All / Disconnect All, профили с их состоянием, настройки, выход
- **Active connections** — между профилями и настройками показываются имя и IP каждого
  подключённого туннеля. Клик по строке копирует IP, показывает «Copied» и **не закрывает меню**;
  при наведении появляется подсказка

### Нативное поведение macOS
- Стандартные `NSAlert` для ошибок, окно «О программе» с версией
- `Cmd+,` открывает настройки в том же окне
- Запоминаются размер и позиция окна; минимальный размер контролируется

## Требования

- **macOS 13 (Ventura)** или новее (тестировалось до macOS Tahoe)
- **Apple Silicon** (arm64): `ngateconsoleclient` от КриптоПро — arm64-бинарник
- Установленный `ngateconsoleclient`, по умолчанию `/opt/cprongate/ngateconsoleclient`
  (для токенов также КриптоПро CSP и драйвер токена)
- Для сборки из исходников: Xcode / Swift 6 (Swift Package, без внешних зависимостей)
- Профиль Ngate VPN с сертификатом (SHA1 + PIN) или логином и паролем

## Установка

### Готовая сборка (рекомендуется)

1. Скачайте `Ngate2VPN-<версия>.dmg` со страницы [Releases](https://github.com/MoonMig/Ngate2VPN/releases)
2. Перетащите `Ngate2VPN.app` в «Программы»
3. Сборки не нотаризованы (нет Developer ID), поэтому при первом запуске macOS может сообщить о
   «недоверенном разработчике»: откройте приложение правым кликом → **Открыть** или выполните
   `xattr -dr com.apple.quarantine /Applications/Ngate2VPN.app`
4. При первом обращении к Keychain выберите **Always Allow**

> При обновлении с версий до 4.00 DNS Helper потребует однократной переустановки
> (Settings → DNS Helper) — обновился привилегированный скрипт.

### Сборка из исходников

```bash
git clone https://github.com/MoonMig/Ngate2VPN.git
cd Ngate2VPN
./Scripts/setup-signing-identity.sh   # один раз: локальная подпись (см. ниже)
./build-app.sh                        # release; ./build-app.sh debug — отладочная
open build/Ngate2VPN.app
```

Скрипт `build-app.sh`:
- запускает `swift build -c release`
- компилирует `libngategate.dylib` (для прогрева) в бандл
- собирает `.app` в `build/Ngate2VPN.app` и `build/Ngate2VPN-<версия>.dmg`
- подписывает локальной идентичностью `Ngate2VPN Local Signing`, если она создана
  (`./Scripts/setup-signing-identity.sh`, один раз), иначе ad-hoc — тогда «Always Allow» для
  Keychain сбрасывается при каждом обновлении

Тесты: `swift test` (63 теста; тест удержания прогретого клиента на 150 с включается отдельно:
`NGATE2VPN_SLOW_TESTS=1 swift test --filter WarmProcessTests`).

### Настройка пути к бинарнику

Откройте **Settings → Application → Binary** и укажите путь к `ngateconsoleclient`.
Если файл не найден — появится предупреждение.

## Добавление профиля

1. Нажмите **`+`** на вкладке Home
2. Заполните **Name**, **URL** шлюза (например `https://vpn.example.com`) и **Auth**
3. В зависимости от метода:
   - **Certificate** — SHA1-отпечаток + PIN
   - **Login** — логин и пароль (при 2FA подтверждайте вход в приложении сразу после запуска)
4. Опционально включите **Auto-reconnect**
5. **Save** — PIN/пароль сохраняются в Keychain; поля профиля их больше не показывают
   (пустое поле = «без изменений»)

## DNS Helper

### Что это и зачем

При подключении к корпоративному VPN нужно направить запросы для `*.company.local` через VPN,
а всё остальное — через обычный DNS. macOS поддерживает это через файлы `/etc/resolver/<domain>`
с содержимым вида `nameserver 10.0.0.1`; для записи в эту папку нужен root.

DNS Helper:
1. При подключении парсит DNS-настройки из ответа шлюза
2. Создаёт файлы в `/etc/resolver/`
3. Сбрасывает кэш `dscacheutil` и `mDNSResponder`
4. При отключении туннеля удаляет свои файлы

**Hold Default DNS** (по умолчанию включён) — приложение не трогает системный резолвер и
перехватывает только конкретные домены. Если выключить, DNS шлюза применяется как системный
через `networksetup -setdnsservers` на всех активных сетевых службах (файла `/etc/resolver/.`
не существует — стандартный резолвер macOS так не настраивается); при отключении DHCP-DNS
восстанавливается.

### Архитектура

Без Apple Developer ID нельзя ни использовать `SMAppService.daemon` (launchd отвергает
ad-hoc-подписанные daemon-binaries), ни `NEDNSSettings` (нужен entitlement от Apple).
Решение — правило `sudoers.d`:

```
# /etc/sudoers.d/ngate2vpn
<ваш_логин> ALL=(root) NOPASSWD: /usr/local/libexec/ngate2vpn-dns-apply.sh
```

Правило разрешает конкретному пользователю запускать **ровно один скрипт** без пароля.
Скрипт принимает команды через stdin:

```
WRITE example.com 10.0.0.1 10.0.0.2   # /etc/resolver/example.com
REMOVE old.example.com
WRITE_DEFAULT 1.1.1.1                 # системный DNS через networksetup
REMOVE_DEFAULT
FLUSH
UNINSTALL_SELF example.com other.example.com
```

Домены проверяются по `[a-z0-9.-]+`, IP — по `[0-9a-fA-F.:]+`; никаких `eval` и подстановок.
Если исходный текст скрипта меняется (новая версия приложения), приложение видит несовпадение
хеша и просит переустановить helper (один запрос пароля).

### Жизненный цикл

| Действие                            | Диалог пароля? |
|-------------------------------------|----------------|
| Settings → DNS Helper → Install     | ✅ один раз    |
| Подключение / отключение туннеля    | ❌             |
| Quit (Cmd+Q) — авто-очистка         | ❌             |
| Запуск после Force Quit             | ❌ (auto-cleanup) |
| Settings → DNS Helper → Uninstall   | ❌             |

При Cmd+Q приложение ждёт, пока асинхронная очистка удалит все созданные файлы. После Force Quit
список созданных файлов лежит в `~/Library/Application Support/Ngate2VPN/dns-helper-active.flag` —
при следующем запуске они находятся и удаляются.

### Безопасность

- Правило `sudoers.d` разрешает запуск **ровно одного скрипта**; `visudo -cf` проверяет его перед установкой
- Скрипт и каталог `/etc/resolver` принадлежат `root:wheel` (скрипт — mode `700`): обычный
  процесс пользователя не может подменить DNS без sudo
- Входные данные валидируются дважды (Swift и bash) по whitelist regex
- Пароли не хранятся ни в Keychain, ни на диске в рамках helper'а

## Архитектура

```
AppDelegate (Ngate2VPNApp.swift)
   ├── окно + тулбар ── SwiftUI-интерфейс ── читает AppState (@EnvironmentObject)
   ├── StatusIconManager + меню в трее (ConnectionMenuItemView)
   └── AppState (@MainActor) ── единый источник истины
        ├── tunnels ── TunnelPersistence (UserDefaults, без секретов)
        ├── runtime (живые состояния туннелей)
        ├── TunnelProcessManager → TunnelProcess (ngate-client, прогрев через libngategate)
        ├── TokenMonitor (IOKit) / GateSupport (прогрев)
        ├── SecretVault → KeychainSecretStore (один элемент Keychain)
        ├── FileLogger → LogWriterActor (actor, асинхронные логи)
        ├── DNSPolicyController (+ NgateGatewayResponseParser) → DNSApplier (/etc/resolver/)
        └── чистая логика без состояния: NgateOutputParser, WatchdogPolicy, ProxyPreflight
```

### Основные модули

| Файл                          | Назначение                                                |
|-------------------------------|-----------------------------------------------------------|
| `Ngate2VPNApp.swift`          | Жизненный цикл, AppDelegate, окно, тулбар, меню в трее    |
| `AppState.swift` + `AppState+*.swift` | Состояние и логика (файлы: Connection, Watchdog, Prewarm, Logging, Alerts, Secrets) |
| `TunnelModels.swift`          | Конфигурация, ошибки, runtime-состояние                   |

| `Support/ngategate.c`         | Библиотека, удерживающая прогретый клиент перед `connect()` |

### Конкурентность

- `AppState` — `@MainActor`, единый источник истины для UI
- `FileLogger` — Swift actor, изолирующий доступ к диску
- `DNSApplier` — `@MainActor` для состояния, `Task.detached` для shell-вызовов
- `ProcessRunner` — отдельные `DispatchQueue` для каждого туннеля
- `Combine` — реактивные обновления политик и состояний

## Устранение проблем

### «Binary not found»
Проверьте путь в Settings → Application → Binary. Файл должен быть исполняемым (`chmod +x`).

### «Invalid server URL»
URL должен включать схему: `https://vpn.example.com`.

### «Invalid credentials»
Для cert-auth: SHA1 сертификата + PIN. Для login-auth: логин и пароль. После нескольких ошибок
шлюз может временно заблокировать аккаунт.

### «Two-factor confirmation timed out»
Шлюз ждёт подтверждения в приложении второго фактора всего ~15 секунд. Держите приложение
подтверждения под рукой и одобряйте вход сразу после нажатия Connect. Приложение само
повторяет попытку один раз; затем нужно включить туннель заново.

### Постоянные переподключения / «System proxy … not passing traffic»
Клиент ходит к шлюзам через системный прокси. Проверьте, что приложение-прокси работает, и
добавьте адреса шлюзов в его список исключений (bypass/DIRECT). Точная причина — в Journal
(фильтр Errors и System).

### Туннель по сертификату долго подключается
Включите **Pre-warm tunnels** и держите токен вставленным. Первый запуск после старта приложения
тратит ~12 секунд на инициализацию токена (в фоне), дальше подключение занимает секунды.

### DNS Helper не применяет политику
1. Проверьте Journal на ошибки от `[SYSTEM]`
2. Если Settings показывает «DNS Helper code changed» — переустановите helper (Uninstall → Install)
3. Убедитесь, что скрипт и правило существуют:
   ```
   ls -la /usr/local/libexec/ngate2vpn-dns-apply.sh
   sudo cat /etc/sudoers.d/ngate2vpn
   ```
4. Каталог `/etc/resolver` должен принадлежать `root:wheel` (`ls -ld /etc/resolver`); если это не так,
   переустановка helper исправит владельца

### `/etc/resolver/` остался непустым после деинсталляции
Это могут быть файлы других приложений или старых версий: каждый файл — просто
`nameserver <ip>`. Для очистки удалите их вручную через `sudo rm`.

## Конфиденциальность и безопасность

- **Никакой телеметрии и аналитики.** Приложение ничего никуда не отправляет.
- **Все данные локальны.** Учётные данные — Keychain; логи — `~/Library/Application Support/Ngate2VPN/logs/`;
  настройки — `UserDefaults` и Application Support.
- **Секреты не пишутся на диск** вне Keychain, кроме краткоживущего конфига клиента (`0600`),
  который удаляется вместе с процессом; в логи и резервные копии они не попадают.
- **Минимум привилегий.** Root нужен только для записи в `/etc/resolver/` и настройки DNS, и только
  через узкое правило sudoers на конкретный скрипт.
- **Нейтральные сообщения об ошибках Keychain** — без внутренних кодов и системных деталей.
